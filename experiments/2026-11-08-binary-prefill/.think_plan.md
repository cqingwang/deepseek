# DeepSeek TP4 镜像内 prefill 优化计划

## 目标与边界

- 从冻结的 D10 运行态出发，保持
  `spark-ds41f:1030`、模型权重、TP4/ring 拓扑、KV 容量、精度和
  c1-c4 decode 语义不变。
- 主验收口径仍是 cold prefill `8K/16K/32K/64K/128K/256K` 六档 tok/s
  的算术平均值；目标是在 D01 baseline `6,466.45 tok/s` 上增加约
  `2,000 tok/s`。
- decode c1-c4 相对 D10 的允许波动为约 3%；模型输出、perplexity、
  rank1 fraction 和失败数必须保持。
- 新一轮最多 10 次四机部署验证；每次先 `deploy.sh stop`，确认四机
  target 容器为 0，再 `deploy.sh start --target=deepseek`。
- 运行参数与镜像内源码严格区分。Python/TileLang 源码改动构建新的
  immutable candidate 镜像；仅切片大小等实验开关可在同一镜像内切换。

## 起点

- 最佳运行参数：D09 `6,788.80 tok/s`，D10 同配置复核
  `6,776.66 tok/s`。
- 冻结源码：
  `experiments/2026-11-08-multi-size-prefill-acceptance/frozen-best/`。
- 当前镜像：
  `sha256:84a8b73d0993200044b5eceb0892342d34a787416b7ae91e4b38f42fffc63e41`。
- 当前 cold prefill 平均仍距目标约 1,678 tok/s，运行参数已接近上限。

## 候选路径

1. **MoE 输出 exchange 切片调度。** 当前 `MOE_SLICE_TOKENS=4096`，
   65,520-token chunk 会切成 16 片。先在同一 candidate 镜像内比较
   8K/16K 切片，目标是减少固定的 collective/launch 成本；必须确认
   combine 与 exchange 的 overlap 不退化。
2. **SP MoE front 合并。** 在每一序列并行 encoder 层，将 router、
   top-k 与一次 MXFP8 cast 先在本 rank 的 L 行执行，再一次性 all-gather
   较小的 record，替代整份 BF16 行 gather 后每 rank 重复 router/cast。
   现有 trace 的可达上限约 3.9% 的 16K prefill。
3. **DSpark context 预计算。** 先测量 target 输入预处理和 context-KV
   预热的占比；只有确认其独占 GPU 主路径且可保持位级输出时才改。
4. **grid-safe prefill。** 先审计动态行数映射到 CUDA `grid.y` 的 kernel；
   只有在更大 chunk 的收益能够覆盖内存和正确性风险时，才启用
   `>65,535` 行。

每轮只改变一个因果变量；前一轮没有可复现收益时，不叠加下一轮。

## 构建与分发

- 所有源码以本地工作树为唯一来源，经父级单向上传到 spark-a。
- 在 spark-a 构建 candidate 镜像一次。若改动只是 Python/TileLang 源码，
  用 `FROM spark-ds41f:1030` 的薄 candidate 层，不重新编译 vLLM C++；
  若改动触及 native extension/NCCL，才走完整 `bin/spark build image`。
- 构建后核对 image ID、源哈希、base image label 和新增 experiment label。
- 沿物理可达顺序
  `spark-a -> 10.251.20.2 -> 10.251.20.6 -> 10.251.20.10`
  逐跳 `docker save | docker load`，每跳核对 image ID。

## 测量协议与门禁

- 固定模型名 `deepseek-v4.1-flash`、`temperature=0`、`thinking=false`、
  同一 prose/source 语料、cold prefix-cache 条件。
- 每轮先测六档 cold prefill，再测 c1/c4；候选有收益时补 c2/c3。
- 六档平均提升必须大于该次 boot 的噪声；首次 candidate 要有同镜像
  repeat 或相同配置复启动确认。
- 四机 running、`OOMKilled=false`、restart count 0、memguard active、
  API HTTP 200、无 Xid/NVRM/OOM/fault；失败启动必须保留 rank 日志。
- 最终输出 SHA-256、perplexity 和 rank1 fraction 必须与 D10 基线一致。

## 收尾

- 每次有收益或有信息量的参数/镜像均落盘到 `runs/` 与 `arms/`。
- 最终只保留最佳方案运行；清理 candidate 临时 overlay、`docker save`
  archive、失败镜像和未引用构建缓存，禁止全系统 prune。
- 更新 `spark/docs/engineering-memory.md`，记录候选镜像 ID、源码哈希、
  每轮六档结果、decode/质量门禁、分发路径和回滚镜像。
- 不提交 Git，不切分支，不 reset；保留任务相关 worktree 修改。
